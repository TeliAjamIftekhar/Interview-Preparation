3. Amazon Bedrock ecosystem

What Amazon Bedrock provides

Amazon Bedrock is a managed service for accessing foundation models and building generative AI applications through AWS APIs. It reduces the need to host and operate model-serving infrastructure yourself. It provides model access plus application-building capabilities such as Knowledge Bases, Guardrails, Agents, evaluation, and related tooling.

Core components

ComponentPurposeInterview explanation
Foundation ModelsText, embedding, image, and other model capabilities from supported providers.Choose based on quality, latency, context window, modality, region availability, throughput, and cost.
Bedrock Runtime / Converse APIInvoke models using APIs.Use the Converse interface for a consistent message-oriented interaction where supported; use model-specific APIs when specialized features are needed.
Knowledge BasesManaged RAG workflow for connecting data sources, indexing, retrieval, and grounded generation.It simplifies common RAG plumbing, but retrieval quality still depends on source quality, chunking, metadata, embeddings, and evaluation.
AgentsManaged agent capability that interprets a request, plans steps, and invokes configured action groups or knowledge sources.Useful when managed orchestration and action-group integration fit; compare with custom orchestration for control and complex state.
Action GroupsExpose API operations or functions to an Agent, commonly through an API schema and Lambda integration.Define narrow, validated operations. The backend must authorize and validate every action.
GuardrailsApply configured controls to model inputs and outputs, including supported content and policy filters.Guardrails are one layer, not a replacement for application authorization, input validation, or security controls.
Model EvaluationSupport evaluation workflows for model performance and quality.Use representative datasets and task-specific metrics; do not rely on a few manual prompts.

Bedrock Agent execution flow

  1. User sends a request to the application.
  2. Application invokes the Agent runtime with the user/session context.
  3. The Agent interprets the request and determines whether it needs knowledge retrieval or an action.
  4. For an action, the Agent selects an Action Group operation and passes structured parameters.
  5. The configured Lambda or API executes validated business logic and returns a structured result.
  6. The Agent uses the result to formulate a response; the application records trace and outcome data.
Important distinction: An Agent deciding to call a tool does not mean the tool call is automatically safe. Your service must authenticate the caller, authorize the operation, validate parameters, enforce business rules, and log the outcome.

Bedrock Agent vs custom LangGraph/Strands orchestration

Choose managed Bedrock Agents when…Choose custom orchestration when…
You want a managed agent abstraction, action groups, and Bedrock-native integration.You need precise state transitions, custom routing, complex loops, deterministic control, or framework flexibility.
The workflow maps well to the managed agent lifecycle.The workflow has many domain-specific stages, explicit checkpoints, or advanced recovery logic.

4. Strands Agents and Amazon Bedrock AgentCore

Strands Agents

Strands Agents is an open-source SDK approach for building agents around a model, instructions, and tools. It is designed to make tool-using agent development straightforward while allowing developers to extend behavior with their own tools and integrations. It is a framework/SDK, not the same thing as a managed Bedrock Agent.

  • Model: the LLM that interprets the request and decides whether to use tools.
  • System prompt/instructions: defines role, boundaries, and expected behavior.
  • Tools: functions the agent can invoke, with schemas and implementation code.
  • Agent loop: model response → tool selection → tool execution → tool result → model response, until completion or a stopping condition.

Prepare to explain tool schemas, tool output formats, error handling, maximum iterations, timeouts, and how you prevent the model from inventing tool results.

AgentCore: understand it as an agent deployment/runtime platform

Amazon Bedrock AgentCore is a set of capabilities intended to help build, deploy, operate, and govern agents. Its capabilities have evolved, so check the current AWS documentation for exact component names and regional availability before an interview.

Capability areaWhat to understand
RuntimeRun agent workloads in a managed environment with attention to isolation, scaling, and session behavior.
GatewayExpose tools and services through a controlled interface; understand authentication and tool discovery.
IdentityManage agent access to resources and delegated credentials securely.
MemorySupport useful context across interactions; decide what should be retained and for how long.
ObservabilityTrace agent steps, tool calls, latency, errors, and outcomes.
Evaluations / policy controlsMeasure agent quality and enforce appropriate operational boundaries where supported.
Do not mix these terms: Bedrock Agents is a managed agent-building capability. Strands is an agent SDK/framework. AgentCore is a platform of agent infrastructure capabilities. They solve related but different parts of the lifecycle.

Sample interview answer

“I see Strands as the developer framework for defining an agent and its tools, while AgentCore addresses the infrastructure needed to operate agents more reliably, such as runtime, identity, gateway, memory, and observability capabilities. Bedrock Agents is another managed option, especially when its action-group and knowledge-base workflow fits the use case. I would select based on the level of orchestration control, operational requirements, and integration constraints.”

5. Multi-agent architecture and orchestration

A multi-agent system separates a complex task into bounded responsibilities. The design should improve control or quality enough to justify extra model calls, latency, cost, and failure modes.

Common patterns

  • Supervisor–worker: a supervisor routes subtasks to specialist agents and combines results.
  • Sequential pipeline: each stage consumes the previous stage's output.
  • Parallel fan-out/fan-in: independent specialists work in parallel; a coordinator aggregates results.
  • Hierarchical: a coordinator delegates to sub-coordinators and specialist agents.
  • Human approval: sensitive or high-impact actions pause for human review.

Be clear about the boundary: an LLM can extract, classify, summarize, and recommend. Deterministic business rules and authorized core-system services should control coverage calculations, eligibility, payment limits, and final approvals. Human review should remain for defined high-risk cases.

State and recovery design

  • Use a typed, explicit state object: claim ID, document status, fraud indicators, coverage result, decision, approvals, errors, and trace ID.
  • Make nodes idempotent where possible. Repeating a node should not create duplicate payments or duplicate records.
  • Set bounded retries for transient failures; use exponential backoff with jitter where appropriate.
  • Do not retry permanent errors such as invalid input or denied authorization.
  • Persist checkpoints before and after critical stages; support safe resume from a known state.
  • Use a dead-letter or exception path for exhausted retries and alert an operator.
  • Record who approved an action, what evidence they saw, and what changed.

How to answer “Why not one agent?”

“A single agent can be simpler and cheaper, so I would start there if the task is straightforward. I would split into specialists when responsibilities need different instructions, tools, access permissions, evaluation criteria, or independent failure handling. The supervisor coordinates them, while deterministic services enforce business rules. I would monitor whether the decomposition actually improves accuracy and maintainability enough to justify extra latency and cost.”

6. RAG engineering — from ingestion to evaluation

End-to-end RAG pipeline

Source documents
  -> parsing / OCR
  -> cleaning and normalization
  -> chunking + metadata
  -> embedding model
  -> vector index (and optional lexical index)

User question
  -> authentication + query validation
  -> query rewrite / expansion (if justified)
  -> embedding
  -> vector / hybrid retrieval
  -> metadata + access-control filtering
  -> reranking (optional)
  -> top-K context assembly
  -> grounded prompt + model
  -> citation / claim validation
  -> answer or abstention
  -> feedback + telemetry

Key concepts

ConceptPractical explanation
ChunkingSplit documents into retrieval units. Respect headings, sections, tables, and semantic boundaries; avoid arbitrary splits that separate a question from its answer.
OverlapSmall overlap can preserve context across chunk boundaries, but excessive overlap adds duplicate retrieval and cost.
EmbeddingsDense numerical representations that place semantically related text near one another in vector space.
Vector searchFind semantically similar chunks by vector distance/similarity.
Lexical searchFind exact terms, names, IDs, and rare keywords. Useful alongside semantic search.
Hybrid searchCombine lexical and semantic retrieval, often followed by score fusion or reranking.
Metadata filteringRestrict retrieval by department, document type, date, tenant, or user authorization.
RerankingRe-score retrieved candidates against the query to improve ordering; adds compute and latency.
AbstentionDecline to answer when evidence is missing, conflicting, or below a defined confidence/evidence threshold.

How to evaluate RAG

  • Retrieval: Recall@K, Precision@K, Hit Rate@K, MRR, nDCG.
  • Generation: answer correctness, faithfulness/groundedness, relevance, completeness, citation correctness.
  • System: latency (median/p95), error rate, token usage, cost per request, throughput.
  • Safety: unauthorized retrieval rate, sensitive-data leakage, prompt-injection success rate, unsafe action rate.

Build a representative golden dataset with questions, expected source documents or passages, expected answer facts, and cases that should be refused. Keep a held-out set to avoid tuning only to the examples used during development.

Your Enterprise Knowledge Assistant — metrics to explain

Your project notes report a 30-question retrieval set with 100% document Hit/Recall, MRR 0.9444, and Top-1 90%. They also report a Top-K comparison where K=3 reduced estimated inference cost by about 21% compared with K=5 while preserving the reported document Hit/Recall on that test set.

Qualify the result: say “on our 30-question evaluation set,” not “100% recall in production.” Explain dataset size, relevance labels, how recall was calculated, and what the metric does not prove. A small evaluation set is useful evidence, not a universal guarantee.

Common RAG failure modes

  • Wrong or incomplete source parsing → improve OCR, table extraction, and document validation.
  • Relevant passage not retrieved → inspect chunk boundaries, query wording, embeddings, filters, and top-K.
  • Correct passage ranked too low → hybrid retrieval or reranking.
  • Answer unsupported by context → stronger grounding instructions, evidence checks, abstention, and citation validation.
  • Cross-tenant leakage → enforce authorization filters outside the model and test adversarially.

7. MCP, tool calling, and function calling

What MCP is

The Model Context Protocol (MCP) is an open protocol for connecting AI applications to external tools and context providers through a standard interface. It helps separate the agent/client from the implementation of a tool server.

  • MCP host: the AI application that contains or coordinates the model experience.
  • MCP client: the protocol client that connects to an MCP server.
  • MCP server: exposes capabilities such as tools, resources, or prompts.
  • Tools: callable operations with defined input schemas and results.
  • Resources: data/context exposed for the client to read.

MCP vs direct function calling

Direct function/tool callingMCP
Application defines and integrates tool schemas and implementations directly.Standardized protocol for discovering and invoking capabilities from MCP servers.
Simple for a small, fixed set of tools in one application.Useful when tools should be reusable across compatible clients and servers.
Application owns most integration conventions.Protocol standardizes communication, but authentication, authorization, validation, and governance are still required.

Tool security checklist

  • Use allow-listed tools; do not let model text become arbitrary shell, SQL, or URL execution.
  • Validate input against a strict schema and enforce business constraints in code.
  • Authenticate the user and authorize each tool operation using least privilege.
  • Separate read-only tools from write or financial actions.
  • Require human confirmation for high-impact or irreversible operations.
  • Set timeouts, rate limits, payload limits, and bounded retries.
  • Log caller, tool name, validated arguments, result status, and trace ID while avoiding secrets and unnecessary personal data.

When to use Step Functions instead of an agent loop

Use Step Functions for explicit business workflows with known stages, durable state transitions, predictable retries, waits, and human approval. Use an agent loop when the next tool or reasoning step depends on the user's request and model-driven decisions. Many enterprise systems use both: an agent proposes or selects an action, while Step Functions governs the approved business process.

9. IAM, KMS, and responsible AI

Security principles

  • Least privilege: grant each Lambda role or agent identity only the actions and resources it needs.
  • Separation of duties: separate ingestion, retrieval, administration, and high-impact execution permissions.
  • Encryption: use TLS in transit and KMS-backed encryption at rest where supported and required.
  • Network controls: private connectivity and restrictive network policies where appropriate.
  • Secrets: use a managed secret store; never hard-code API keys in source code or prompts.
  • Tenant isolation: enforce user/tenant authorization before retrieval and before tool execution.
  • Auditability: preserve trace IDs, decision evidence, tool outcomes, approvals, and model/config versions.

Guardrails are not authorization

Guardrails can help filter or constrain model inputs and outputs according to configured policies. They do not prove that a user is permitted to read a document or execute a transaction. Enforce access control in the application and data layer.

Prompt injection defenses

  1. Treat retrieved documents and tool outputs as untrusted data, not system instructions.
  2. Keep system instructions separate from retrieved content.
  3. Restrict tool capabilities and validate every argument.
  4. Do not expose secrets or internal prompts to the model unnecessarily.
  5. Use allow-listed destinations and constrained network egress for tools.
  6. Test direct and indirect prompt injection with adversarial evaluation cases.

Responsible AI themes

Fairness, reliability, safety, privacy, transparency, explainability, accountability, and human oversight. Translate these into concrete controls: representative evaluation data, documented limitations, refusal behavior, appeal/escalation routes, audit logs, and human review for high-impact decisions.

10. SageMaker and MLOps fundamentals

Be ready to distinguish a foundation-model application built on Bedrock from a custom ML lifecycle managed with SageMaker. They can complement one another.

Typical ML lifecycle

  1. Data preparation: ingest, validate, clean, label, split, and version datasets.
  2. Experimentation: train models, track parameters and metrics, compare baselines.
  3. Evaluation: test on holdout data; assess accuracy and relevant business/safety metrics.
  4. Registration: store approved model artifacts and metadata in a model registry.
  5. Deployment: deploy to a real-time endpoint, batch transform, or another suitable inference pattern.
  6. Monitoring: monitor latency, errors, data quality, drift, and model performance where labels become available.
  7. Retraining: trigger a governed retraining process when data or performance conditions justify it.
TermMeaning
TrainingLearn model parameters from a training dataset.
InferenceUse a trained model to produce predictions on new inputs.
Batch inferenceProcess a dataset in batches; useful when immediate responses are not required.
Online inferenceServe predictions through an endpoint for low-latency requests.
Data driftInput data distribution changes compared with the reference distribution.
Concept driftThe relationship between inputs and target outcomes changes over time.

Bedrock vs SageMaker — interview framing

“I would generally consider Bedrock when I want managed access to foundation models and GenAI application capabilities without managing model hosting. I would consider SageMaker when I need more control over the ML lifecycle, such as custom training, experimentation, model registry, endpoints, and monitoring. The choice depends on customization, model ownership, operational requirements, and cost.”

13. System-design scenarios to practise

Scenario 1: Design a secure enterprise RAG assistant for multiple departments.

Cover identity → API → authorization → department/tenant filtering → retrieval → grounded generation → citations → abstention → telemetry. Explain how you prevent unauthorized chunks from entering the model context.

Scenario 2: Design an agent that can update customer records.

Use narrow tools, server-side authorization, schema validation, idempotency, confirmation for writes, audit logs, rate limits, and rollback/compensation where possible. The LLM should not have direct database credentials.

Scenario 3: Design a long-running claims workflow.

Use Step Functions for durable orchestration, Lambda for bounded tasks, DynamoDB or a suitable store for business state, EventBridge for events, and human approval for exceptions. Define retries, catches, timeouts, DLQs, and resume behavior.

Scenario 4: RAG quality has dropped after adding 100,000 documents.

Check ingestion failures, parsing quality, duplicate content, chunk distribution, metadata, index health, embedding consistency, query mix, retrieval recall, ranking, and latency. Compare before/after with a fixed evaluation set.

Scenario 5: Agent tool calls are slow and expensive.

Measure per-step latency and token use; reduce unnecessary reasoning loops; use deterministic routing for predictable tasks; parallelize independent work; cache safe repeatable reads; limit tool payloads; select a suitable model; and set budgets/timeouts.

System-design answer structure

  1. Clarify users, workload, data sensitivity, and success criteria.
  2. State functional and non-functional requirements.
  3. Draw the high-level architecture and request flow.
  4. Explain data model, APIs, and service responsibilities.
  5. Cover security, privacy, and tenant isolation.
  6. Cover failure handling, observability, and recovery.
  7. Discuss trade-offs, cost, latency, and scaling.
  8. Define evaluation and operational success metrics.

15. Interview question bank

Open each question to reveal the answer points. Practise speaking the answer before opening it.

1. What is the difference between RAG and fine-tuning?

RAG retrieves external knowledge at query time and supplies it as context. Fine-tuning changes model parameters using training examples. RAG is often better for frequently changing or source-cited knowledge; fine-tuning is useful for behavior, style, or task adaptation. They can be combined.

2. What happens when an agent calls a tool?

The model returns a structured tool request. The application validates the tool name and arguments, checks authorization, executes the function, captures the result or error, and returns a structured tool result to the model. The model then continues or completes. The application controls limits and permissions.

3. What is the difference between LangChain and LangGraph?

LangChain provides components and abstractions for LLM applications, tools, retrieval, and chains. LangGraph focuses on stateful graph-based orchestration with nodes, edges, conditional routing, cycles, checkpointing, and human-in-the-loop patterns. They can be used together.

4. What is the difference between an agent and a workflow?

A workflow follows predefined steps and transitions. An agent uses a model to select actions or tools based on context. Use workflows for predictable, regulated processes; use agents where flexible interpretation or dynamic tool selection adds value. A robust system often combines both.

5. What is a Bedrock Knowledge Base?

A managed capability that connects supported data sources to an indexing and retrieval workflow for RAG. It can handle ingestion, embeddings, vector storage integration, retrieval, and grounded generation features depending on configuration. It does not remove the need to evaluate relevance, permissions, and answer quality.

6. What is an Action Group?

A set of actions exposed to a Bedrock Agent, commonly described with an API schema and implemented through Lambda or an API integration. The action implementation must validate inputs and enforce authorization and business rules.

7. What is the purpose of AgentCore?

It provides infrastructure capabilities for deploying and operating agents, with areas such as runtime, gateway, identity, memory, and observability. Explain the specific capabilities relevant to the architecture and verify current service details against AWS documentation.

8. What is Strands Agents?

An open-source SDK/framework for building model-driven agents using instructions and tools. The agent loop lets the model choose a tool, the runtime executes it, and the result is returned for the model to continue. It is distinct from a managed Bedrock Agent.

9. How do you reduce hallucinations in RAG?

Improve source quality and retrieval; use metadata filters and reranking; constrain generation to supplied evidence; require citations; validate citation support; use an abstention threshold; and evaluate with answerable and unanswerable questions. No single prompt guarantees zero hallucinations.

10. What is the difference between Precision@K and Recall@K?

Precision@K measures how many of the retrieved top-K results are relevant. Recall@K measures how many of all known relevant items were retrieved in the top K. Precision rewards fewer irrelevant results; recall rewards finding the relevant evidence.

11. What is MRR?

Mean Reciprocal Rank averages 1 divided by the rank of the first relevant result across queries. A relevant result at rank 1 contributes 1.0; at rank 2 contributes 0.5. It measures how early the first relevant result appears.

12. Why use hybrid search?

Dense retrieval captures semantic similarity; lexical search captures exact terms and rare keywords. Hybrid search combines both, which can improve coverage for enterprise content containing IDs, product names, policy terms, and natural-language questions. It must be measured on the target corpus.

13. How do you handle a failed tool call?

Classify the failure as transient, permanent, authorization-related, or business-rule-related. Retry only transient failures with bounded exponential backoff; validate inputs; return structured errors; checkpoint state; and escalate exhausted or high-risk failures. Never blindly repeat a non-idempotent action.

14. What is idempotency?

Repeated execution with the same logical request produces the same intended outcome without duplicating side effects. Use an idempotency key and conditional writes or transaction controls, and persist the processing result so retries can safely return the prior outcome.

15. Lambda or Step Functions?

Lambda runs a unit of compute. Step Functions coordinates a workflow across tasks and states, with branching, retries, waits, catches, and execution history. A Lambda can be a task inside a Step Functions workflow.

16. EventBridge or SQS?

EventBridge is an event bus for routing events to targets using rules and event patterns. SQS is a message queue that buffers work and decouples producers and consumers. They can be combined; choose based on routing versus queueing and consumer-processing needs.

17. How do you secure an agent?

Authenticate users, authorize every operation, grant least-privilege tool permissions, validate arguments, isolate tenants, encrypt data, protect secrets, constrain network access, add human approval for risky actions, and log tool calls and decisions.

18. What is prompt injection?

An attacker attempts to make the model ignore intended instructions or misuse retrieved content/tools. Defenses include treating external content as untrusted, separating instructions and data, restricting tools, enforcing authorization in code, and testing indirect prompt injection.

19. How would you monitor an agent in production?

Track end-to-end and per-step latency, token use, cost, model and prompt versions, tool calls, success/error rates, retries, user feedback, retrieval metrics, groundedness, and safety events. Use correlation IDs and avoid logging sensitive content unnecessarily.

20. How do you choose an LLM?

Evaluate quality on representative tasks, latency, cost, context window, tool-use reliability, structured output, language needs, safety, availability, throughput, and deployment constraints. Run a controlled evaluation rather than choosing only by benchmark reputation.

21. What is human-in-the-loop?

A workflow pauses for a human to review, approve, reject, or correct a result before continuing. Define clear triggers, present evidence and proposed action, record reviewer identity and decision, and support timeout/escalation.

22. What is the difference between data drift and concept drift?

Data drift is a change in the input distribution. Concept drift is a change in the relationship between inputs and target outcomes. Both can reduce model performance and require monitoring and investigation.

23. How do you process a large multi-page invoice?

Store it in S3, start an asynchronous Textract job, track job status, collect results, normalize fields, validate totals and required fields, route uncertain cases to review, persist results, and use idempotency and DLQ/replay controls.

24. Why not let the LLM directly query the database?

Direct unrestricted access creates security, data leakage, correctness, and audit risks. Expose narrow parameterized tools or approved query templates, enforce user authorization, validate inputs, limit returned fields, and log execution.

25. How do you reduce agent latency?

Profile each step, reduce unnecessary agent loops, choose an appropriately sized model, shorten prompts and tool payloads, parallelize independent calls, cache safe repeatable reads, avoid redundant retrieval, and set timeouts and budgets. Measure p50 and p95 before and after.
